## 1. IoT 系統的基本元件 {{考科二 1-1｜補充（能力指標 3：系統元件與架構）}}
| 元件 | 角色 | 例子 |
|---|---|---|
| 感測器 Sensor（輸入） | 把物理量轉成電訊號 | 溫濕度、光、加速度、電流、超音波 |
| 致動器 Actuator（輸出） | 把電訊號轉成動作 | 馬達、繼電器、電磁閥、LED、蜂鳴器、伺服機 |
| 控制器／運算單元 | 讀感測、做判斷、下指令 | MCU（Arduino、ESP32）、單板電腦（Raspberry Pi）、PLC |
| 通訊模組 | 連網 | Wi-Fi、BLE、Zigbee、LoRa、NB-IoT、4G/5G、Ethernet、RS-485 |
| 閘道器 Gateway | 協定轉換、資料前處理、暫存、安全、上雲 | 把 Zigbee／Modbus 轉成 MQTT／HTTP |
| 電源 | 供電與穩壓 | 電池、變壓器、穩壓 IC（如 3.3 V LDO）、太陽能 |
| 雲端平台／伺服器 | 收集、儲存、分析、裝置管理 | MQTT Broker、資料庫、Dashboard、規則引擎 |
| 應用介面 | 給人看與操作 | 手機 App、Web 儀表板、告警通知 |

> **💡 記法**：「**感（輸入）→ 控（判斷）→ 動（輸出）**」是單機；加上「**通（通訊）→ 雲（平台）→ 用（應用）**」才是物聯網。

## 2. 控制器怎麼選：MCU、單板電腦、PLC {{考科二 1-1｜補充（能力指標 3）}}
| 類型 | 特性 | 優點 | 限制 | 典型 |
|---|---|---|---|---|
| MCU 微控制器 | CPU＋記憶體＋I/O 整合在一顆晶片，通常**不跑完整作業系統**（裸機或 RTOS） | 便宜、省電、開機即用、即時性好 | 記憶體與算力小 | Arduino Uno（ATmega328P，8 位元，5 V）、ESP32（內建 Wi-Fi＋BLE，3.3 V） |
| MPU／單板電腦 SBC | 處理器需外接記憶體，**跑 Linux 等作業系統** | 算力強、可跑資料庫、Python、AI 推論、多工 | 較耗電、需正常關機、開機慢 | Raspberry Pi（GPIO 為 3.3 V） |
| PLC 可程式邏輯控制器 | 工業級控制器，梯形圖等語言 | 耐環境、穩定可靠、即時控制 | 價格高、彈性較小 | 產線設備控制 |
| 工業電腦 IPC／邊緣閘道器 | 工業級電腦 | 可跑邊緣運算與多協定轉換 | 成本較高 | 機台聯網、Edge AI |

> **⚠️ 易混淆**：Arduino Uno 的 I/O 是 **5 V**，ESP32 與 Raspberry Pi 的 GPIO 是 **3.3 V**（不耐 5 V）；混接要加**電壓準位轉換**。Raspberry Pi **沒有內建 ADC**，讀類比感測器要外接 ADC 晶片（如經 SPI 或 I²C）。

A. Arduino Uno 開發板
B. Raspberry Pi 單板電腦

D. 手機 App

> PLC 是工業級控制器：耐環境、穩定可靠、即時控制，缺點是價格較高、彈性較小，正符合產線設備控制。Arduino、Raspberry Pi 偏向開發與原型，耐環境與可靠度不如 PLC。
:::

## 3. 「端－邊－雲」架構與資料流 {{考科二 1-1｜補充（能力指標 3）}}
| 層 | 位置 | 工作 |
|---|---|---|
| 端（Device／感知層） | 現場感測器、致動器、MCU | 擷取資料、執行控制 |
| 邊（Edge／閘道器） | 現場附近 | 協定轉換、過濾與彙整、即時判斷、斷線暫存（store and forward） |
| 雲（Cloud／平台） | 資料中心 | 長期儲存、大數據分析、AI 訓練、裝置管理、跨場域監控 |

典型資料流：**感測器 → 訊號調理（放大、濾波）→ ADC → MCU → 通訊模組 → 閘道器 → 雲端（Broker／API）→ 資料庫 → 儀表板／App**；若要**閉迴路控制**，雲端或邊緣的判斷結果再下行到 MCU 驅動致動器（例如溫度過高 → 開風扇）。

**架構設計的取捨考量**：功耗（電池多久）、傳輸距離、頻寬與資料量、即時性（延遲）、可靠度、成本、資安、擴充性、維運（OTA 更新、遠端監控）。

> **💡 例子（智慧溫室規劃）**：土壤濕度與溫濕度感測器（類比／數位）→ ESP32 → LoRa 或 Wi-Fi → 閘道器 → MQTT Broker → 時序資料庫 → Dashboard；濕度低於門檻時，由邊緣端直接驅動繼電器開啟灌溉電磁閥（即使網路中斷也能運作），雲端負責趨勢分析與通知。

## 4. 工業現場的元件分層 {{考科二 1-1｜補充（能力指標 3）}}
| 層級 | 元件 | 功能 |
|---|---|---|
| 現場層 | 感測器、致動器、變頻器、伺服 | 量測與動作 |
| 控制層 | PLC、控制器 | 即時邏輯控制 |
| 監控層 | **HMI**（人機介面）、**SCADA**（監控與資料擷取） | 畫面監看、警報、遠端操作 |
| 製造管理層 | **MES**（製造執行系統） | 工單、生產追蹤、品質、績效 |
| 企業層 | **ERP**（企業資源規劃） | 訂單、採購、財務、庫存 |

設備聯網常以 OPC UA、MTConnect、Modbus 等標準把現場資料送到上層（D3 已學）。MES 與 ERP 在 D11 會再深入。

## 5. 故障排除的方法論 {{考科二 1-2｜補充（能力指標 3：系統故障問題判斷與排除）}}
1. **先確認現象與範圍**：是全部裝置還是單一裝置？一直發生還是偶發？什麼時候開始？最近改過什麼？
2. **由簡入繁、由外而內**：先查電源、接線、指示燈，再查設定、程式、網路、雲端。
3. **分層排查**（對照 OSI）：實體（電源、線路、訊號）→ 鏈結／網路（連線、IP）→ 傳輸（埠號）→ 應用（帳密、主題、格式）。
4. **分段隔離（二分法）**：從資料流中間切開測試，例如「MCU 序列埠有讀值嗎？」有 → 問題在後段；沒有 → 問題在前段。
5. **一次只改一個變數**，並**做紀錄**；修好後確認根本原因（Root Cause），避免再發生。
6. **替換法**：用已知良品替換可疑元件（感測器、線材、電源）。


:::check 考科二 1-2
工廠 50 台相同的溫度監測裝置中，只有 1 台在儀表板上停止更新，其他 49 台正常。依故障排除方法論，最合理的第一步是？
A. 立刻重新安裝雲端的 MQTT Broker
B. 修改全部裝置的 Topic 命名
C. 既然問題只在單一裝置，先從該台的電源、接線、指示燈與連線狀態查起

= C
> 先確認範圍：49 台正常代表 Broker 與共通設定大致沒問題，應聚焦單一裝置，並由簡入繁、由外而內。D 一次改太多變數，修好也不知道根本原因。
:::

## 6. 常見故障「症狀 → 原因 → 處理」 {{考科二 1-2｜補充（能力指標 3）}}
| 症狀 | 常見原因 | 檢查與處理 |
|---|---|---|
| 裝置完全不動作、指示燈不亮 | 電源未接、電壓不足、極性反接、保險絲斷 | **三用電表**量供電電壓；檢查變壓器規格 |
| 馬達或繼電器一啟動，MCU 就重開機 | 負載瞬間電流造成**電壓下陷（brownout）**、共用電源 | 致動器獨立供電、加大電源容量、加電容；共地 |
| 感測讀值一直是 0 或最大值 | 接線鬆脫、腳位設定錯、感測器沒供電、**未共地** | 檢查接線與程式腳位；量感測器輸出電壓 |
| 讀值跳動、雜訊大 | 接地不良、線太長、電源雜訊、靠近馬達 | 加濾波電容／RC 濾波、軟體平均或中位數濾波、雙絞屏蔽線、遠離干擾源 |
| 序列埠出現亂碼 | **鮑率不一致**、資料格式（如 8N1）不符、TX/RX 沒交叉、RS-232 與 TTL 準位不同 | 兩端設定一致、TX 接 RX、加準位轉換 |
| I²C 掃不到裝置 | 位址錯或**位址衝突**、**缺上拉電阻**、SDA/SCL 接反、線過長 | 用 I²C 掃描程式確認位址；加上拉電阻；縮短線長 |
| SPI 讀不到資料 | 片選 CS 沒拉低、SPI 模式（時脈極性／相位）不符、MISO/MOSI 接反 | 對照規格書設定 |
| Wi-Fi 連不上 | SSID 或密碼錯、**裝置只支援 2.4 GHz**（如 ESP8266）卻連 5 GHz、訊號弱、拿不到 IP | 檢查頻段與訊號強度（RSSI）、DHCP |
| 有連網但連不到伺服器 | IP／DNS 設定、防火牆擋埠、伺服器沒開 | **ping** 測連通、**traceroute** 看路徑、**nslookup** 查 DNS、確認埠號 |
| MQTT 收不到訊息 | Broker 位址或埠號錯（一般 **1883**、TLS **8883**）、**Topic 拼字或大小寫不同**、帳密錯、**Client ID 重複**互踢 | 用 MQTT 測試工具訂閱 `#` 觀察；核對 Topic |
| Modbus RTU 沒有回應 | 從站位址（Slave ID）錯、鮑率／同位元不符、**RS-485 的 A/B 線接反**、長線缺終端電阻（約 120 Ω）、暫存器位址偏移（40001 對應位址 0） | 逐項核對通訊參數與接線 |
| 資料時間戳錯亂 | 裝置時鐘未同步 | 啟用 **NTP** 校時 |
| 系統跑一段時間當機 | 記憶體不足或洩漏、無限迴圈、電源不穩 | 加**看門狗（Watchdog）**自動重啟、檢查記憶體使用 |

## 7. 故障排除工具箱 {{考科二 1-2｜補充（能力指標 3）}}
| 工具 | 用途 |
|---|---|
| 三用電表（萬用電表） | 量**電壓、電流、電阻、通路（蜂鳴）**；查供電與斷線 |
| 示波器 | 看**訊號波形**、雜訊、PWM、時序 |
| 邏輯分析儀 | 擷取多路數位訊號並**解碼 UART／I²C／SPI** |
| 序列埠監控（Serial Monitor） | 看 MCU 印出的除錯訊息與讀值 |
| ping／traceroute／nslookup／ipconfig（ifconfig） | 網路連通、路徑、DNS、IP 設定 |
| 封包分析（如 Wireshark） | 看實際封包內容與協定 |
| MQTT 用戶端工具、Postman | 測 Broker 訂閱發布、測 REST API |

> **⚠️ 易混淆**：量**電流**要把電表**串聯**在電路中；量**電壓**要**並聯**；量**電阻**要先**斷電**。


:::check 考科二 1-2

B. 感測器沒有供電
C. MQTT 的 QoS 設定太低

:::
