## 1. 中介軟體與平台的範圍 {{考科一 2.4｜指引 p.4-73～4-74}}
指引定義：感測資料經**感測閘道器**接收後，一直到提供 AIoT 應用服務之間的**所有軟體元件與通訊協定**；在 IoT 分層上涵蓋**網路層與應用層**。

**(1) 閘道器的連線技術**：Ethernet、Datacom（4G/5G）、Wi-Fi、LPWAN；工業環境另有 RS232/485、Modbus、EtherCAT。分成兩類協定：
- **實體層（硬體）協定**：定義電壓、接腳、連線方式。
- **網路層（軟體）協定**：定義通訊格式與內容。
- 例：智慧城市常用 **Ethernet＋TCP/IP**；工業常用 **RS232/485＋Modbus RTU** 或 **Ethernet＋Modbus TCP/IP**。
- 有線區域網路最普及的標準是 **IEEE 802.3（Ethernet）**，如 100Base-T／1000Base-T，用雙絞線或光纖。

**(2) 網路層協定**：負責定址與路由，常見 **IPv4、IPv6**；其上再由傳輸層（TCP/UDP）提供端對端傳輸、應用層（HTTP、Modbus TCP、DNS）處理應用格式。

## 2. 訊息中介軟體 {{考科一 2.4｜指引 p.4-74～4-75}}
感測器多、資料量暴增時，加入**訊息中介軟體**當緩衝，把「資料接收」與「應用處理」**解耦（Decoupling）**。

| 協定 | 對應軟體 |
|---|---|
| MQTT、AMQP | RabbitMQ、Apache ActiveMQ |
| Kafka | Kafka |

四個要點：
- **QoS**：最多一次、最少一次、剛好一次（概念同 MQTT QoS）。
- **Pub/Sub 角色**：Publisher（產生者）、Subscriber（接收者）、Broker（分派者），依 Topic 分派。
- **資料保存**：訊息在分派前不能因斷電當機遺失 → 選具**永久儲存（Persistent Storage）**能力的，如 **Kafka**。
- **高併發緩衝**：暫存後逐一分派，保護後端電腦與資料庫不被衝垮，也讓後端規格能用 CP 值較高的方式設計。

## 3. 地端、純雲、混合雲與 IaaS/PaaS/SaaS {{考科一 2.4｜指引 p.4-75～4-77}}
| 架構 | 說明 | 例 |
|---|---|---|
| 地端 On-Premise | 營運與管理屬於企業內部（實體機或 VMware、Proxmox 虛擬化），重點不是機器規模 | 小型或封閉系統 |
| 純雲 Pure-cloud | 所有軟體元件都在雲端業者環境內 | S3／Cloud Storage、RDS／Cloud SQL、EC2／Compute Engine、AWS IoT Core／GCP Pub/Sub |
| 混合雲 Hybrid-cloud | 部分資料與邏輯在地端、部分在雲端 | 原因：資料安全、內部網路、上雲速度與規劃耗時 |

| 服務模型 | 雲端給你什麼 | 你要自己管什麼 | 例 |
|---|---|---|---|
| IaaS 基礎設施即服務 | 虛擬網路、虛擬電腦等**虛擬硬體** | OS、資料庫版本更新、備份、應用 | 租 EC2 自己裝 SQL Server |
| PaaS 平台即服務 | 在 IaaS 上整合 OS、執行環境、資料庫、網頁伺服器、維運 | 主要只管應用程式 | **AWS RDS／GCP Cloud SQL**（已含修補與備份）、AWS IoT Core、Vertex AI |
| SaaS 軟體即服務 | 直接可用的軟體服務 | 只管使用與設定 | 應用業者部署給終端客戶的服務 |

- 指引觀點：**PaaS 對應用業者最有價值**，可降低 **CI（持續整合）、CD（持續交付／持續部署）、DevOps** 的負擔；不用 PaaS 的話，跟傳統 IDC 機房模式差不多。

> **⚠️ 易混淆**：「提供作業系統、程式執行環境、資料庫及網頁伺服器的開發平台」＝ **PaaS**（指引 p.4-80 練習題）。自己裝資料庫＝IaaS；用託管資料庫＝PaaS。


:::check 考科一 2.4
某工廠因資安規定，產線即時控制資料與配方必須留在廠內伺服器；但跨廠報表分析與長期資料保存希望放到雲端，以便擴充。這種架構最符合下列哪一種？
A. 純雲（Pure-cloud）
B. 地端（On-Premise）
C. 混合雲（Hybrid-cloud）
D. SaaS
= C
> 部分資料與邏輯在地端、部分在雲端＝混合雲；指引列出的常見原因包含資料安全與內部網路需求。純雲是全部在雲端業者環境；地端是全部由企業內部營運；SaaS 是服務模型，不是部署位置。
:::

## 4. 應用層的決策：儲存、通訊、驗證、分析、服務 {{考科一 2.4｜指引 p.4-77～4-79}}
**(1) 資料儲存**
| 資料型態 | 例 | 存放 |
|---|---|---|
| 結構化 | 表格欄位固定的感測紀錄 | **關聯式資料庫**：嚴謹結構、以鍵值關聯；提供 **ACID**（原子性 Atomicity、一致性 Consistency、隔離性 Isolation、持久性 Durability） |
| 半結構化 | **JSON、YAML、XML** | **NoSQL**：特色是**橫向擴充**、對大數據友善 |
| 非結構化 | 圖文檔案、圖片 | 物件儲存（如 S3）、向量資料庫；經 OCR、向量計算可轉成半結構化 |
| 高時效 | 即時查詢 | **記憶體快取（Memory-cache）**：Redis、Memcached（< 5 ms） |

**(2) 元件間通訊模式**：請求-回應（HTTP、REST、gRPC、GraphQL）、非同步訊息驅動（AMQP、MQTT、Kafka）、遠端程序呼叫 RPC（gRPC、Apache Thrift、Apache Dubbo）。

**(3) 身分驗證機制**
| 機制 | 特性 | 適用 |
|---|---|---|
| X.509 憑證 | 安全性極高，但運算與管理複雜、資源負擔重 | 閘道器、車聯網 |
| Token（JWT、Basic Auth、Bearer token） | 輕量簡單 | 應用服務的軟體元件 |
| 共享金鑰 PSK（Pre-shared key） | 運算最輕 | **算力極低的設備** |
| 硬體安全模組 TPM、HSM | 做密碼學運算，遭惡意破壞也不洩漏金鑰 | 高安全硬體 |
| 帳號密碼 | 最基本 | 使用者登入 |

**(4) 資料分析三層次**：統計與描述性分析（中位數、標準差、極值＋Dashboard、Alert）→ 資料探勘與關聯分析（找離群點、分群；需大量 **ETL：擷取 Extract、轉換 Transform、載入 Load** 清洗資料，再用 **Hadoop、Spark、BigQuery** 處理海量資料）→ **AI/ML**。

**(5) 服務提供**：APP（Android/iPhone，原生 Java/Swift 或跨平台 Flutter）與 WEB（本質是 HTML＋JavaScript＋CSS）。

{{考科一 2.4｜指引 p.4-80～4-84 練習題}} 練習題重點：雲端讓感測元件不需強大算力、易擴展；但**雲端即時處理的主要挑戰是網路延遲較高**；雲端資安考量應是**最小權限**而非最大權限；大數據工具（Hadoop）的價值在「**資料處理與分析能力**」。


:::check 考科一 2.4
平台團隊先用中位數、標準差、極值等指標整理每日感測資料，並以儀表板（Dashboard）與告警（Alert）呈現。依指引的「資料分析三層次」，這屬於哪一層？
A. 統計與描述性分析
B. 資料探勘與關聯分析
C. AI／機器學習
D. ETL 資料載入
= A
> 指引的三層次為：統計與描述性分析（中位數、標準差、極值＋Dashboard、Alert）→ 資料探勘與關聯分析（找離群點、分群，需大量 ETL）→ AI/ML。ETL 是資料清洗的過程，不是分析層次。
:::

## 5. 資安三大技術：加密、雜湊、簽章 {{考科一 2.5｜指引 p.4-85}}
| 技術 | 解決什麼 | 常見演算法／重點 |
|---|---|---|
| 對稱式加解密 | 防**竊聽**（機密性），雙方用**同一把金鑰** | AES、DES、Twofish；需金鑰交換：**DHE、ECDH（Elliptic Curve DH）** |
| PSK 預載金鑰 | 感測節點算力弱，避免複雜的非對稱金鑰交換 | Sensor node 可明文或用 PSK 加密 |
| 雜湊 Hash | 不易由結果反推原文；**輕量地保護密碼、API 金鑰**；單獨使用只能確保**完整性** | SHA256、SHA512、SHA3 |
| 數位簽章（非對稱） | 證明「確實是他發的、內容沒被假造」→ **不可否認性（Non-repudiation）** | 私鑰簽、公鑰驗 |

> **💡 非對稱金鑰口訣**：要**保密**給 B → 用 **B 的公鑰**加密，B 用自己的私鑰解；要**簽章**證明是 A → A 用**自己的私鑰**加密（簽），B 用 **A 的公鑰**解（驗）。（指引 p.4-91 練習題：A 用自己的金鑰加密，B 用 A 的公鑰解開）

## 6. IoT 常見風險與攻擊 {{考科一 2.5｜指引 p.4-86～4-87}}
- **預設帳號密碼／弱加密**（如 RC2、RC4）：攻擊者用自動化工具掃描取得存取權。
- **韌體漏洞**：IoT 更新不易且數量多，已知漏洞可存在數年；加入 **OTA** 更新機制可改善，但不是每台都有算力。
- **網路攻擊**：中間人攻擊（MITM）、殭屍網路（Botnet）、阻斷服務（DoS）、分散式阻斷服務（DDoS）、竊聽、竄改。
- **實體入侵**：透過電路板上的 **JTAG/UART/Console** 直接取得管理權限 → 量產設備應**關閉 JTAG/Console**。
- 被大量入侵的 IoT 可能**反過來變成攻擊工具**，發動 Botnet 攻擊下游（Edge、Cloud server）→ 重要系統要做**網路隔離（Network isolation）**，切斷橫向攻擊。

> **💡 經典案例**：**Mirai** 感染數十萬台攝影機、路由器組成殭屍網路，發動 **DDoS**（指引 p.4-91 練習題）。

## 7. 資安核心觀念：AAA、CIA、裝置與平台防護 {{考科一 2.5｜指引 p.4-86～4-88}}
| 框架 | 內容 |
|---|---|
| **AAA** | 認證 Authentication（你是誰）、授權 Authorization（依身分給權限）、稽核 Auditing（事後追查時間、人員、結果） |
| **CIA** | 機密性 Confidentiality（加密、身份驗證、遮罩、存取控制）、完整性 Integrity（雜湊；**訊息鑑別碼 MAC**）、可用性 Availability（SLA、Load Balancer 高可用；會被 DDoS、SYN Flood、Broadcast Storm 降低） |

- **SLA 換算**：99% ≈ 每月 7.2 小時停機；99.99% ≈ 每月 4.3 分鐘。
- **裝置防護**：閘道器注意預設密碼、實體接線、韌體 N 日攻擊；**韌體簽章（Secure boot）＋OTA encryption**；裝置認證依能力選 PSK、API key、Token、**mTLS**、X.509；通訊依重要性選加密、MAC、簽章。
- **平台防護**：**防火牆白名單**（Layer 2/3，限制來源 IP 與 port，簡單快速）；**WAF 網頁應用程式防火牆**（拆到應用層，可防 **SQL Injection、XSS、Bot attack**）。
- 練習題：**認證方式中「密碼」防護較差**（生物特徵如靜脈、瞳孔、指紋不易偽造）；**中繼器（Repeater）無法做網路隔離**，VLAN、防火牆、不同 SSID 可以；鐵殼保護 PLC **無法防 DoS**。

## 8. 資料安全：DR、RPO、RTO 與 SDLC 掃描 {{考科一 2.5｜指引 p.4-88～4-89}}
| 名詞 | 意思 | 例 |
|---|---|---|
| DR 災難復原 | 災難後如何快速恢復系統與資料 | — |
| **RPO** 復原點目標 | **最多會遺失多少時間的資料** | 一天備份一次 → RPO＝24 hr |
| **RTO** 復原時間目標 | **系統要多久恢復服務（停機時間）** | 靠雲端部署、多用 PaaS、CI/CD 縮短 |

> **💡 記法**：RP**O**＝資料「**點**」回到哪裡（丟多少資料）；RT**O**＝「**時間**」多久回來（停多久）。

SDLC 資安掃描：開發階段**靜態程式碼弱點掃描**、**第三方函式庫（套件）弱點掃描**、測試階段對運行中系統做**弱點掃描**、上線前與定期做**滲透測試**。


:::check 考科一 2.5
某 IoT 平台即將上線。資安團隊在上線前，由專人「模擬駭客實際攻擊」運行中的系統，嘗試找出可被利用的漏洞。依 SDLC 資安掃描，這項工作稱為？
A. 靜態程式碼弱點掃描
B. 第三方函式庫弱點掃描
C. 滲透測試
D. 災難復原演練
= C
> 上線前與定期由專人模擬攻擊＝滲透測試。靜態程式碼掃描在開發階段檢查原始碼；第三方函式庫掃描檢查套件的已知漏洞；災難復原（DR）是災後恢復，不是找漏洞。
:::

## 9. 物聯網隱私四原則 {{考科一 2.5｜指引 p.4-89～4-90}}
| 原則 | 意思 | 例 |
|---|---|---|
| 匿名化／假名化 Anonymization / Pseudonymization | 遮罩去識別化，或把識別資料換成匿名編號，處理到無法追溯個人 | 感測資料與個資在同表或可 Join 時要處理 |
| 資料最小化 Data minimization | 只收集應用所需的必要資料 | 門禁只記進出時間，不錄整段影像 |
| 告知與同意、可攜與刪除 | 告知收集哪些資料並取得同意；使用者可要求**匯出**與**刪除** | — |
| 目的限制 | 告知用途；**要用在其他用途（例如匯入 AI 分析）須再次取得同意** | — |

{{考科一 2.5｜補充}} 一般區分：**匿名化**＝不可逆、無法再識別；**假名化**＝以代號取代，持有對照表仍可回推。指引將兩者並列說明，考題若問「無法追溯到個人」選匿名化較穩。

> **⚠️ 易混淆**：**DDoS 監控**屬可用性防護，**對防止個資外洩沒有直接幫助**；傳輸加密、身份認證與權限管控、去識別化才是（指引 p.4-92 練習題）。


:::check 考科一 2.5
社區智慧門禁蒐集住戶進出紀錄時，告知的用途是「門禁管理」。管委會後來想把這些紀錄匯入 AI 分析住戶作息，用於社區行銷活動。依物聯網隱私原則，最恰當的做法是？
A. 資料已經蒐集了，可以直接使用
B. 只要資料有加密，就可以用於新用途
C. 要用於原告知目的以外的用途，須再次取得住戶同意
D. 只要不對外公開分析結果，就不需告知
= C
> 「目的限制」：告知用途後，若要用在其他用途（例如匯入 AI 分析）須再次取得同意。加密保護的是機密性，不能取代同意；不公開也不代表可以超出原目的使用。
:::
