今天要搞懂五件事：第一，雲端數據收集的流程。第二，JSON、XML、CSV 的語法和優缺點，能找出格式錯誤。第三，REST API 的方法和狀態碼，以及 MQTT 主題命名設計。第四，關聯式資料庫設計：主鍵、外鍵、正規化、基本 SQL。第五，NoSQL 和時序資料庫，IoT 資料該存哪裡。

第一段，這段對應考科二 2-2，雲端環境數據收集與平台設計，先看平台架構。
流程有六個階段。擷取：裝置讀取感測值，加上時間戳和裝置 ID。傳輸：用 MQTT、HTTP、CoAP、WebSocket 送到雲端。接收：MQTT Broker、API 閘道、IoT 平台負責接入和驗證裝置。處理：清洗、轉換、規則判斷、告警，可以是即時串流或批次，像 Node-RED。儲存：依資料特性選資料庫。應用：視覺化、分析、AI、對外 API，像 Grafana 儀表板。順序記成：擷取、傳輸、接收、處理、儲存、應用。
平台設計考量：可擴充性，裝置變多時水平擴充；可靠性，斷線重傳、資料不遺失；即時性；資安；成本；資料保存政策，原始資料留多久、舊資料降採樣彙總；還有裝置管理，包含註冊、狀態、OTA。
資料量估算例子：一千台裝置，每十秒上傳一筆，每筆兩百位元組，一天大約一點七 GB。這種估算會決定要不要在邊緣先彙整。

第二段，考科二 2-2，資料交換格式。
先講 JSON。物件用大括號，裡面是「鍵、冒號、值」；陣列用中括號。重點：鍵必須用雙引號，字串也要用雙引號，不能用單引號。值的型別有字串、數字、布林的 true 和 false、null、物件、陣列。JSON 不允許註解，也不允許最後一個元素後面多一個逗號。陷阱：true 和 null 不加引號，加了引號就變成字串了。
再講 XML。標籤要成對、區分大小寫、正確巢狀、只能有一個根元素、屬性值要加引號，符合這些叫做格式良好，英文 well-formed。XML 可以用 XSD 或 DTD 驗證結構，有命名空間，但比較冗長。
三者比較：JSON 簡潔、檔案小、支援巢狀，常用在 REST API、MQTT 酬載、NoSQL 文件。XML 冗長、檔案大，用在舊系統、設定檔、SOAP，以及 OPC UA、MTConnect 的資訊模型。CSV 檔案最小，但只有平面表格，沒有標準驗證，用在匯出報表。另外，二進位格式像 CBOR、Protocol Buffers，比 JSON 更省頻寬，適合資源受限的裝置。

第三段，考科二 2-2，API 與主題設計。
REST API 用 HTTP 方法對資源做新增、讀取、更新、刪除：GET 讀取，POST 新增，PUT 整筆更新、PATCH 部分更新，DELETE 刪除。
狀態碼：二開頭是成功，二百 OK、二零一 Created。四開頭是用戶端錯誤：四百格式錯誤，四零一未認證，四零三無權限，四零四找不到。五開頭是伺服器錯誤，像五百、五零三。請特別分清楚：四零一是「你是誰我不知道」，未認證；四零三是「我知道你是誰，但你沒權限」。
MQTT 主題設計：用斜線分層，從大到小，例如工廠 A、斜線、產線一、斜線、機台零五、斜線、溫度。加號匹配單一層，井字號匹配其下所有層，而且井字號只能放最後。主題區分大小寫，不要以斜線開頭，也不要有空白。命令和資料要分開，例如 cmd 和 data 兩個主題。

第四段，考科二 2-2，關聯式資料庫設計。
資料表由欄位和資料列組成。主鍵，唯一識別每一列，不可重複、不可為空值。外鍵，參照另一張表的主鍵，建立關聯、維持參照完整性。關聯類型有一對一、一對多，像一台裝置有很多筆讀值，以及多對多，需要中介表。索引可以加快查詢，但會增加寫入成本和空間。
IoT 範例：裝置表以裝置 ID 為主鍵；讀值表有自己的讀值 ID 當主鍵，再用裝置 ID 當外鍵，連回裝置表。
正規化，目的是減少重複資料和更新異常。第一正規化：每個欄位都是不可再分的單一值，反例是一個欄位存三個溫度用逗號隔開。第二正規化：非鍵欄位要完全依賴整個主鍵，消除部分相依，反例是主鍵是訂單號加產品號，卻存了只依賴訂單號的客戶名稱。第三正規化：消除遞移相依，非鍵欄位不能依賴其他非鍵欄位，反例是在讀值表裡存裝置的安裝地點。口訣：一正單一值，二正去部分相依，三正去遞移相依。
SQL 分三類：DDL 定義結構，像 CREATE、ALTER、DROP；DML 操作資料，像 SELECT、INSERT、UPDATE、DELETE；DCL 管權限，像 GRANT、REVOKE。交易的 ACID：原子性，全做或全不做；一致性；隔離性；持久性。
陷阱：UPDATE 或 DELETE 忘了加 WHERE 條件，會影響整張表。DROP TABLE 是刪掉整張表，連結構帶資料；DELETE 只刪資料列。

第五段，考科二 2-2，NoSQL 與時序資料庫。
關聯式資料庫，固定綱要、用 SQL、有 ACID、可以 JOIN，像 MySQL、PostgreSQL，適合裝置清單、使用者、工單這些結構化主資料。文件型，存 JSON 類文件，綱要彈性，像 MongoDB，適合不同型號欄位不一的資料。鍵值型，像 Redis，適合存裝置最新狀態和快取。寬欄型，像 Cassandra，適合海量寫入。圖形資料庫，像 Neo4j，適合設備拓樸。
最重要的是時序資料庫，像 InfluxDB、TimescaleDB：以時間戳為主軸、高速寫入、時間區間查詢、支援降採樣和保存政策，還會壓縮，是感測讀值和設備監控最典型的選擇。
NoSQL 多數以水平擴充和高可用為優先，常採最終一致性，也叫 BASE；關聯式重視強一致和 ACID。常見的混合設計：主資料放關聯式，感測讀值放時序資料庫，最新狀態放快取，影像等原始檔案放物件儲存。
