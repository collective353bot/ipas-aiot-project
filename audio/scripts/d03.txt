哈囉，歡迎收聽 iPAS AIoT 應用工程師初級有聲講義第三天。今天主題是應用層協定與工業通訊標準：MQTT、CoAP、HTTP 和 REST、Modbus、OPC UA、MTConnect。這天的內容非常常考，建議多聽幾次。

今天要搞懂五件事：第一，MQTT、HTTP、CoAP 的底層協定、通訊模式、標頭大小和適用場景。第二，MQTT 的三個角色、主題、QoS 零一二、Keep Alive、遺囑訊息、保留訊息。第三，封裝和解封裝，TCP 對比 UDP。第四，OPC UA 的特性和四種資料存取方式，MTConnect 的四元素。第五，Modbus 的三種模式和四種資料區塊，還有 RESTful API 的方法和狀態碼。

第一段，這段對應考科一 2.2，為什麼 IoT 需要輕量協定。
裝置連上網之後，下一個問題是：資料要怎麼封裝和交換？HTTP 是為網頁設計的，在硬體資源受限、網路不穩的 IoT 環境顯得笨重，所以出現了 MQTT、CoAP 這些輕量協定。

第二段，考科一 2.2，MQTT、HTTP、CoAP 三者比較。
MQTT，底層走 TCP，通訊模式是發布訂閱，中間有一個 Broker，標頭最小只有兩個位元組，主動推播、即時性高，靠 QoS 機制保證可靠性，適合大規模感測網和即時控制。MQTT 是 IBM 在一九九九年為了監控輸油管線開發的。
HTTP，底層也是 TCP，模式是請求回應，標頭很大，有數百位元組，伺服器沒辦法主動推播給裝置，要靠輪詢，除非用 WebSocket。適合韌體更新、影像傳輸、Web 介面。
CoAP，底層走 UDP，也是請求回應，支援 REST 的 GET、POST、PUT、DELETE，標頭四個位元組，可以想成輕量版 HTTP，不需要維持長連線，適合極低功耗感測器、NB-IoT 設備、智慧電表。陷阱：CoAP 沒有 QUERY 這種請求方法。
所以記住：MQTT 是 TCP 加發布訂閱加兩個位元組；CoAP 是 UDP 加 REST 加四個位元組。
另外，WebSocket 建立後可以雙向即時通訊，適合視訊、即時監看。指引練習題認為 HTTP 在伺服器回應後會斷線，而 Socket、WebSocket、FTP 不會。嚴格說這是 HTTP 1.0 的行為，但考試照指引答 HTTP。

第三段，這段對應考科一 2.3，封裝與解封裝。
指引這節用 TCP/IP 五層說明：應用層、傳輸層、網際網路層、資料連結層、實體層。封裝，就是資料往下傳，每一層加上自己的標頭；解封裝，就是接收端往上傳，逐層把標頭拿掉。資料連結層把封包封成訊框，用 MAC 位址定址，常見設備是交換器；實體層包含電纜、光纖、網路卡、中繼器。
以 Modbus 為例：應用程式要讀保持暫存器，函式庫先轉成 Modbus PDU，也就是功能碼加資料欄位。如果是 Modbus TCP，就加上 MBAP 標頭，再經 TCP、IP 送出；如果是 Modbus RTU 或 ASCII，就加上裝置位址和錯誤檢查碼，CRC 或 LRC，經過 RS-232 或 RS-485 傳輸。
TCP 跟 UDP 比較：TCP 是連接導向，傳輸前要三次握手，保證按順序、完整到達，比較慢，用在檔案、網頁、MQTT、Modbus TCP。UDP 無連接，不保證可靠和順序，但是快，用在影音串流和 CoAP。練習題還考過：LAN 是小範圍、一棟建築物的網路；IPv4 由四組零到二五五的數字用點分隔。

第四段，考科一 2.3，為什麼工廠要從 Modbus 走向 OPC UA。
傳統工控普遍用 Modbus，簡單可靠，但設計時沒有考慮資安，沒有加密和身分驗證。現代製造要安全的資料交換，所以導入 OPC UA 這種提供加密、身分驗證和授權的進階協定。

第五段，考科一 2.3，OPC UA。
OPC UA 由 OPC 基金會開發，被視為工業 4.0 的關鍵標準。特性：第一，平台獨立，從嵌入式 MCU 到雲端都能實作，不是只限 Windows。第二，內建多層次安全：認證、授權、資料完整性、加密通訊。第三，可擴展的資訊模型。第四，多語言實作。第五，主從架構，也就是 Client/Server，Server 通常在設備端，把控制器和感測器資料轉成標準格式。第六，可以把各廠牌設備函式庫封裝在 OPC UA Server，形成設備聯網閘道器平台。第七，促進水平與垂直整合，從設備到 MES 到 ERP。
四種資料存取方式，必考。一，讀寫：主動讀變數或寫新值，例如寫入新的進給率。二，資料變更通知：訂閱變數，值改變時伺服器通知你，例如機器溫度超過閾值。三，方法：遠端呼叫伺服器提供的方法，例如遠端觸發自動換刀。四，事件通知：訂閱事件，被動接收，例如緊急停機、機器手臂故障。
易混淆：資料變更訂閱的是「變數值的變化」，事件通知訂閱的是「事件」，像故障、警報。另外，資訊模型裡的 NodeId 不能重複；練習題認為 OPC UA 對應 OSI 第七層，應用層。

第六段，考科一 2.3，MTConnect。
專門為製造業、特別是工具機設計的開放標準。三個關鍵字：唯讀、XML、HTTP。它免授權費、可擴展、可讀性好。
四元素資料流：設備，也就是 CNC、機器人；適配器 Adapter，存取設備資料並轉成 XML，例如發那科用 FOCAS 函式庫；代理器 Agent，是核心，整合一個或多個 Adapter 的資料，透過 HTTP RESTful API 提供出去；最後是應用程式，拿資料做分析、監控。順序：設備、適配器、代理器、應用程式。
跟 OPC UA 對比：OPC UA 可讀可寫、主從架構、資安內建；MTConnect 唯讀、XML 走 HTTP。

第七段，考科一 2.3，MQTT 深入。
三角色：發布者、訂閱者、中介代理者 Broker。發布者帶著主題把訊息送給 Broker，Broker 依主題過濾，推播給訂閱該主題的訂閱者。從主從角度看，發布者和訂閱者都是 Client，Broker 是 Server，而且發布者不知道有多少訂閱者。這叫解耦：感測器故障，手機 App 不會掛；App 離線，感測器照樣送到 Broker。
三個機制：Keep Alive，客戶端定期送訊息維持連線、偵測斷線。遺囑訊息 LWT，裝置非正常斷線，例如沒電、網路斷，Broker 代為發送預設的遺囑訊息。TLS，負責加密和身分驗證。另外還有保留訊息，Broker 保留一份最新訊息，讓新加入的訂閱者立刻收到。

第八段，考科一 2.3，MQTT QoS 三等級，必考。
QoS 零，最多一次，不確認、不重傳，可能遺失，最省資源。QoS 一，至少一次，沒收到確認就重傳，保證到達但可能重複，接收方要能處理重複。QoS 二，恰好一次，四步驟握手，保證只收到一次，最耗資源，用在計費、控制指令這種關鍵訊息。口訣：零是丟了就算，一是一定到可能兩次，二是剛剛好一次。沒有 QoS 三。

第九段，考科一 2.3，Modbus。
用在 PLC、溫控器、伺服驅動器，採主從架構，不支援加密與身分驗證。Modbus TCP 常用五零二埠。三種模式：RTU 用二進位編碼，效率高，錯誤檢查用 CRC 循環冗餘檢查；ASCII 用 ASCII 編碼，可讀性好，錯誤檢查用 LRC 縱向冗餘檢查；TCP 走乙太網路，錯誤檢查交給 TCP。
四種資料區塊：線圈 Coil，位元，可讀可寫，位址零開頭，控制開關。離散輸入，位元，唯讀，位址一開頭。輸入暫存器，十六位元，唯讀，位址三開頭，讀溫度壓力。保持暫存器，十六位元，可讀可寫，位址四開頭，設定參數。口訣：零線圈、一離散、三輸入、四保持；能寫的只有線圈和保持暫存器。

第十段，考科一 2.3，RESTful API。
基於 HTTP，用 URL 當資源的唯一識別，用 HTTP 方法做新增、讀取、更新、刪除。GET 讀取，成功回二百 OK，找不到回四零四。POST 建立，成功回二零一 Created。PUT 更新。DELETE 刪除，成功常回二零四 No Content。測試工具：Mock Server 模擬後端，讓前後端平行開發；Postman 模擬客戶端，看狀態碼和回應時間。

口頭自測時間。
第一題：哪個協定底層走 UDP、標頭四個位元組？[停頓]答案是 CoAP。
第二題：MQTT 哪一個 QoS 等級保證到達、但可能重複？[停頓]QoS 一，至少一次。
第三題：裝置突然沒電斷線，由 Broker 代為通知大家，這是什麼機制？[停頓]遺囑訊息，LWT。
第四題：Modbus 中，可讀可寫的十六位元資料區塊是哪一個？[停頓]保持暫存器，位址四開頭。
第五題：OPC UA 中，訂閱緊急停機、被動接收通知，是哪種存取方式？[停頓]事件通知。

三十秒回顧：MQTT 是 TCP、發布訂閱、兩個位元組、有 QoS；CoAP 是 UDP、REST、四個位元組；HTTP 標頭大、要輪詢。封裝加標頭，解封裝去標頭。TCP 可靠，UDP 快。OPC UA 跨平台、內建資安，四種存取：讀寫、資料變更、方法、事件。MTConnect 唯讀、XML、HTTP，設備到適配器到代理器到應用。QoS 零可能遺失、一可能重複、二恰好一次。Modbus RTU 配 CRC、ASCII 配 LRC、TCP 五零二埠，零一三四。POST 二零一、DELETE 二零四。第三天結束，明天見。
