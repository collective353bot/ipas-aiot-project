第一段，對應考科二 2-2，雲端數據收集與平台架構。
六個階段：擷取，裝置讀感測值，加上時間戳和裝置 I D；傳輸，用 M Q T T、H T T P、CoAP、WebSocket 送上雲；接收，由 M Q T T Broker、A P I Gateway 或 IoT 平台接入並驗證裝置；處理，清洗、轉換、規則判斷、告警，可以即時串流或批次；儲存，依資料特性選資料庫；應用，儀表板、分析、A I、對外 A P I。
用手搖飲店比：店員記下「幾點、哪家分店、點了什麼」是擷取；外送平台把單送到總部是傳輸；總部門口確認是自己人是接收；把亂寫的單整理好是處理；歸檔是儲存；老闆看報表是應用。口訣：「擷、傳、收、處、存、用」。
平台設計考量：可擴充性、可靠性、即時性、資安、成本、資料保存政策、裝置管理。
小情境：想像你是平台工程師，一千台裝置、每 10 秒上傳一筆、每筆 200 位元組，一天大約 1.7 G B。這種估算決定要不要先在邊緣彙整，還有資料庫和費用怎麼規劃。

第二段，考科二 2-2，資料交換格式。
J S O N：大括號是物件，裡面是「鍵：值」；中括號是陣列。規則請記：鍵必須用雙引號，字串也要雙引號，不能用單引號；值可以是字串、數字、布林、null、物件、陣列；不允許註解，最後一個元素後面不能多逗號。
考題常這樣問：「下列哪段 J S O N 格式錯誤？」找三個地方：單引號、尾巴多一個逗號、有註解。還有一個陷阱：true 和 null 不加引號，加了引號就變成字串。
X M L：標籤成對、區分大小寫、正確巢狀、只有一個根元素、屬性值加引號，這樣叫格式良好 well formed。可以用 X S D、D T D 驗證，但比較冗長。比喻：J S O N 像便利貼，簡潔；X M L 像正式公文，每段都有開頭和結尾，嚴謹但長；C S V 像 Excel 表格，最小，但只能平面，不能巢狀。
用途：J S O N 用在 REST A P I、M Q T T 酬載、NoSQL 文件；X M L 用在舊系統、設定檔、SOAP，還有 O P C U A、MTConnect 資訊模型；C S V 用在匯出報表。另外，C B O R、Protocol Buffers 是二進位格式，比 J S O N 更省頻寬，適合資源受限的裝置。

第三段，考科二 2-2，A P I 與主題設計。
REST A P I：GET 讀取，POST 新增，PUT 整筆更新，PATCH 部分更新，DELETE 刪除。狀態碼：2 開頭成功，200 OK、201 Created；4 開頭是用戶端錯誤，400 格式錯誤、401 未認證、403 無權限、404 找不到；5 開頭是伺服器錯誤。
401 和 403 很容易搞混。用捷運來記：401 是你沒刷卡，系統不知道你是誰，未認證；403 是你刷了學生卡想進員工通道，系統知道你是誰，但你沒權限。
M Q T T 主題設計：用斜線分層，從大到小，例如 factory A 斜線 line 1 斜線 machine 05 斜線 temp，就像地址從縣市寫到門牌。加號匹配單一層，井字號匹配以下所有層，而且只能放最後。主題區分大小寫，不要用斜線開頭，不要有空白，命令和資料要分開，例如 cmd 和 data。
考題常這樣問：「訂閱 factory A 斜線井字號，會收到什麼？」factory A 底下所有層的訊息。

第四段，考科二 2-2，關聯式資料庫設計。
資料表由欄位和資料列組成。主鍵唯一識別每一列，不能重複、不能空白，像身分證字號。外鍵參照另一張表的主鍵，建立關聯、維持參照完整性。關聯類型：一對一、一對多，例如一台裝置有很多筆讀值，多對多則需要中介表。索引加快查詢，但增加寫入成本，像書後面的索引頁，好查，但每改一次書就要更新。
IoT 範例：devices 表以 device id 當主鍵；readings 表有自己的主鍵，再用 device id 當外鍵。
正規化，減少重複資料和更新異常。1 N F：每個欄位都是不可再分的單一值，不能在一格塞「26.5、27.0、26.8」三個值。2 N F：非鍵欄位要完全依賴整個主鍵，消除部分相依，例如主鍵是訂單號加產品號，卻存只跟訂單號有關的客戶名稱，就違反。3 N F：消除遞移相依，例如在 readings 表裡存裝置的安裝地點，它其實依賴 device id，應該放 devices 表。口訣：「1 單值、2 去部分、3 去遞移」。
S Q L 分類：D D L 定義結構，CREATE、ALTER、DROP；D M L 操作資料，SELECT、INSERT、UPDATE、DELETE；D C L 管權限，GRANT、REVOKE。交易的 A C I D：原子性、一致性、隔離性、持久性。
陷阱兩個：UPDATE、DELETE 忘了加 WHERE，整張表都會被改，像群發簡訊忘了選收件人，全通訊錄都收到。DROP TABLE 是連結構帶資料整張刪，DELETE 只刪資料列。

第五段，考科二 2-2，NoSQL 與時序資料庫。
關聯式：固定綱要、S Q L、A C I D、可以 JOIN，像 MySQL、PostgreSQL，放裝置清單、使用者、工單。文件型，像 MongoDB，存 J S O N 類文件，適合不同型號欄位不一的裝置。鍵值型，像 Redis，存裝置最新狀態、快取。寬欄型，像 Cassandra，大量寫入、水平擴充。圖形資料庫，像 Neo4j，存設備拓樸。時序資料庫，像 InfluxDB、TimescaleDB，以時間戳為主軸、高速寫入、時間區間查詢、降採樣和保存政策，是感測讀值最典型的家。
NoSQL 多數以水平擴充和高可用為優先，常採最終一致性 BASE；關聯式重視強一致和 A C I D。
小情境：想像你要設計一座智慧工廠平台，怎麼分配？主資料放關聯式，感測讀值放時序資料庫，最新狀態放快取，影像原始檔放物件儲存。這就是常見的混合設計。

最後回顧。擷、傳、收、處、存、用。J S O N：鍵用雙引號、沒註解、沒尾逗號、true 和 null 不加引號。X M L：成對、分大小寫、單一根。C S V 只能平面。GET 讀、POST 新增、PUT PATCH 改、DELETE 刪；201 建立、401 未認證、403 無權限、404 找不到。主題由大到小，加號單層、井字號多層。主鍵唯一非空，外鍵參照。1 單值、2 去部分、3 去遞移。D D L、D M L、D C L。感測讀值放時序資料庫。第十天就到這裡，辛苦了，我們明天見！
