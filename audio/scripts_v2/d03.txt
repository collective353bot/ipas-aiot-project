大家好，歡迎回來，這裡是 i PAS，A I o T 應用工程師初級的有聲課，今天是第三天。今天主題是「資料怎麼封裝、怎麼交換」：M Q T T、H T T P、CoAP，封裝與 T C P、U D P，工業界的 O P C U A、MTConnect、Modbus，最後是 RESTful A P I。這天的必考點非常密，我們用很多生活例子把它們串起來。好，出發！

第一段，對應考科一 2.2，為什麼 IoT 需要輕量協定。
連上網之後，下一個問題是：數據怎麼封裝、怎麼交換？H T T P 是為網頁設計的，在硬體資源有限、網路又不穩的 IoT 環境，就像騎機車送一張便條，卻要先把它裝進大紙箱，太笨重了。所以出現了 M Q T T、CoAP 這些輕量協定。

第二段，考科一 2.2，M Q T T、H T T P、CoAP 三者比較。
M Q T T 底層是 T C P，模式是發布訂閱，中間有一個 Broker，標頭最小只有 2 個位元組，有 Q o S 機制，即時性高，會主動推播。它是 I B M 在 1999 年為了監控輸油管線開發的，強調低頻寬、低硬體需求、網路不穩也可靠。
H T T P 是請求回應，標頭大，有幾百個位元組，伺服器沒辦法主動推播，要靠裝置一直輪詢。就像你一直打電話問手搖飲店「我的飲料好了沒」，很累。M Q T T 則像店家叫號系統，好了直接通知你。H T T P 適合韌體更新、影像傳輸、Web 介面。
CoAP 是「輕量版 H T T P」，底層走 U D P，標頭 4 個位元組，也是請求回應，支援 GET、POST、PUT、DELETE，不需要維持長連線，喚醒時間更短，適合極低功耗感測器、N B IoT 設備、智慧電表。
口訣：「M Q T T，T C P 加訂閱，2 位元組；CoAP，U D P 加 REST，4 位元組」。
考題常這樣問：「CoAP 支援哪個請求方法？」陷阱選項是 QUERY，CoAP 沒有 QUERY。另外 WebSocket 建立後可以雙向即時通訊，適合視訊通話、即時監看。指引練習題認為 H T T P 在伺服器回應後就會斷線，而 Socket、WebSocket、F T P 不會。這裡要特別注意標註：回應後就斷線其實是 H T T P 1.0 的預設行為，1.1 預設是持久連線；但考試遇到這種題型，依指引答 H T T P。

第三段，考科一 2.3，封裝與解封裝。
指引 4.3 節用五層說明：應用層、傳輸層、網際網路層、資料連結層、實體層。封裝，就是資料往下傳，每一層加上自己的標頭；解封裝，是接收端往上傳，一層一層拆掉。用寄禮物來想：禮物先包包裝紙，再裝盒子，再貼宅配單；收件人反過來一層一層拆。資料連結層把封包封成訊框，用 M A C 位址定址，常見設備是交換器；實體層有電纜、光纖、網路卡、中繼器。
以 Modbus 為例：讀保持暫存器的指令先變成 Modbus P D U，也就是功能碼加資料欄位。走 Modbus T C P，就加上 M B A P 標頭，再經 T C P、I P 送出；走 R T U 或 A S C I I，就加裝置位址和錯誤檢查碼，C R C 或 L R C，經 R S 232 或 R S 485 傳。

第四段，考科一 2.3，T C P 和 U D P。
T C P 是連接導向，傳之前要三次握手，保證按順序、完整到達，比較慢，像掛號信，要簽收。M Q T T、Modbus T C P 都用它。U D P 無連接，不保證可靠和順序，但快，像發傳單，丟出去就算，適合影音串流和 CoAP。
練習題也常考：L A N 是小範圍，一棟或一組建築物的網路；I P v 4 由 4 組 0 到 255 的數字用點分隔，像 192 點 168 點 0 點 1。

第五段，考科一 2.3，為什麼工廠要從 Modbus 走向 O P C U A。
Modbus 簡單可靠，但設計時沒考慮資安，沒有加密也沒有身分驗證，就像家門沒鎖。現代製造要小批量、多樣化、安全的資料交換，所以導入提供加密、身分驗證與授權的 O P C U A。

第六段，考科一 2.3，O P C U A。
由 O P C 基金會開發，被視為工業 4.0 關鍵標準。特性：平台獨立，從嵌入式 M C U 到雲端都能做，不是只限 Windows；內建多層次安全；可擴展的資訊模型；多語言實作；Client Server 架構，Server 通常在設備端。它可以把各廠牌設備的存取函式庫封裝起來，變成設備聯網閘道器平台，促進從設備到 M E S 再到 E R P 的水平與垂直整合。
四種資料存取方式，必考！想像你是工廠工程師，面對一台 C N C：要讀產品重量、寫入新的進給率，是讀寫；訂閱刀具壽命，數值一變就通知你，是資料變更通知；遠端觸發自動換刀程序，是方法；訂閱緊急停機、手臂故障這類事件，是事件通知。
口訣：「讀寫自己動手，變更盯數字，方法叫它做事，事件等它報警」。
考題常這樣問：「訂閱特定事件、被動接收通知」是哪一個？答案是事件通知，不是資料變更。另外練習題考過：資訊模型裡 NodeId 不能重複；指引解析認為 O P C U A 對應 O S I 第 7 層應用層。

第七段，考科一 2.3，MTConnect。
專為製造業、特別是工具機設計的開放標準，定義一組標準設備參數名稱。三個關鍵字：唯讀、X M L、H T T P。它只讀、不寫指令，像只能看不能點餐的菜單看板。開放源碼、免授權費、基於 X M L 可擴展、人和機器都好讀。四元素資料流：設備，產生主軸轉速等參數；適配器，把設備資料轉成 X M L，例如發那科用 FOCAS；代理器是核心，整合資料，用 H T T P RESTful A P I 提供；最後是應用程式做分析和預測維護。口訣：「設、適、代、應」。
考題陷阱：O P C U A 可讀可寫、內建資安；MTConnect 唯讀。

第八段，考科一 2.3，M Q T T 深入。
三角色：發布者、訂閱者、Broker。用 Line 群組來想：你把訊息丟進主題群組，Broker 依主題轉給所有訂閱的人，發布者不知道有多少人在看。以 Client Server 來看，發布者和訂閱者都是 Client，Broker 才是 Server。好處是解耦：感測器壞了，手機 App 不會掛；App 離線，感測器照樣送到 Broker。
三個機制：Keep Alive，定期送訊息維持連線、偵測斷線；遺囑 L W T，裝置非正常斷線，像突然沒電，Broker 代替它發出預設的遺囑訊息通知大家；T L S，加密和身分驗證。還有保留訊息 Retained Message：Broker 保留一份最新訊息，新加入的訂閱者馬上就能收到，像新同學進群組，馬上看到置頂公告。

第九段，考科一 2.3，M Q T T Q o S 三等級，必考。
Q o S 0，最多一次，不確認不重傳，可能遺失，像寄平信。Q o S 1，至少一次，沒收到確認就重傳，保證到但可能重複，像外送員怕你沒收到，又多按一次門鈴。Q o S 2，恰好一次，四步驟握手，最耗資源，用在計費、控制指令這種關鍵訊息。
口訣：「0 丟了就算，1 一定到可能兩次，2 剛剛好一次」。考題陷阱：沒有 Q o S 3。

第十段，考科一 2.3，Modbus。
P L C、溫控器常用，主從架構，不支援加密與身分驗證，Modbus T C P 常用 502 埠。R T U 是二進制、效率高，用 C R C 檢查；A S C I I 可讀性好，用 L R C；T C P 走乙太網路，錯誤檢查交給 T C P。
四種資料區塊：線圈，位元，可讀可寫，像電燈開關；離散輸入，位元，唯讀，像門有沒有關的指示燈；輸入暫存器，16 位元，唯讀，讀溫度壓力；保持暫存器，16 位元，可讀可寫，設定參數。口訣：「0 線圈、1 離散、3 輸入、4 保持，能寫的只有線圈和保持」。考題常這樣問：「要設定溫控器的目標溫度，寫入哪一區？」答案是保持暫存器，位址 4 開頭。

第十一段，考科一 2.3，RESTful A P I。
基於 H T T P，用 U R L 當資源的唯一識別，用方法做新增、讀取、更新、刪除。用網購來想：GET 是看商品，成功 200，找不到 404；POST 是下訂單建立新資料，成功回 201 Created，格式錯回 400，衝突回 409；PUT 是修改訂單；DELETE 是取消，成功常回 204 No Content，沒權限 403。特性是統一介面、客戶端與伺服器分離。
測試工具：Mock Server 模擬後端，讓前後端平行開發；Postman 模擬客戶端，看狀態碼和回應時間。

好，口頭自測時間！每題念完，你先在心裡作答。
第一題：CoAP 底層走 T C P 還是 U D P？先想一想……好，答案是 U D P。
第二題：M Q T T Q o S 1 的特性是什麼？先想一想……好，答案是保證到達，但可能重複。
第三題：裝置突然沒電斷線，由 Broker 代發通知的機制叫什麼？先想一想……好，答案是遺囑 L W T。
第四題：Modbus 四種區塊中，哪兩種可寫？先想一想……好，答案是線圈和保持暫存器。
第五題：MTConnect 的三個關鍵字？先想一想……好，答案是唯讀、X M L、H T T P。

最後回顧。M Q T T：T C P、發布訂閱、2 位元組、有 Q o S；CoAP：U D P、REST、4 位元組；H T T P 標頭大要輪詢。封裝加標頭，解封裝拆標頭。T C P 掛號信，U D P 發傳單。O P C U A：跨平台、內建資安、讀寫、變更、方法、事件。MTConnect：唯讀、X M L、H T T P，設適代應。Q o S：0 可能丟、1 可能重複、2 剛好一次。Modbus：R T U 配 C R C、A S C I I 配 L R C、T C P 502 埠，0、1、3、4。REST：POST 201、DELETE 204。第三天就到這裡，辛苦了，我們明天見！
